# BIM Diff — локальный бенчмарк

Сравнение BIM-моделей с наложением версий и метриками каждого прогона.
Здесь находятся готовый production runner, исходники локального launcher/сборщика и независимые модули бенчмарка.
Сборка фронтенда уже включена: основной монорепозиторий и его история не нужны.

## Для тестировщика: одна команда

Один раз установите **Node.js 22 или новее** с https://nodejs.org/ (npm/npx входят в установку).
Откройте PowerShell/Terminal и выполните:

```sh
npx --yes https://github.com/NicknameIsAvailable/bim-diff/releases/download/v1.0.1/bim-diff-benchmark-1.0.1.tgz
```

Клонировать репозиторий, устанавливать Git и вводить токены не нужно.
При первом запуске автоматически скачивается Chromium (несколько сотен мегабайт).
Последующие запуски используют кеш. Откроется отдельное окно браузера.
Не закрывайте терминал во время измерений. Закрытие окна браузера или Ctrl+C останавливает приложение.
Порты 4176 и 4177 должны быть свободны; одновременно запускайте только один экземпляр.

## Как провести тест

1. Закройте тяжёлые приложения, подключите ноутбук к питанию; запишите режим энергопотребления.
2. Используйте автоматически открывшийся Chromium: в другом браузере не будет привязанных CPU/RAM-метрик.
3. Выберите одинаковую пару файлов и сценарий на всех устройствах. В комплекте только небольшие тестовые наборы; рабочие IFC/FRAG выбирайте с диска.
4. Заполните сведения об устройстве. Выполните обычный протокол: прогрев + 5 измеряемых повторов с 30 секундами движения камеры. Диагностический короткий прогон не является замером производительности.
5. Держите вкладку видимой. Не двигайте окно между экранами и не меняйте масштаб во время прогона.
6. Нажмите экспорт JSON. Файл сохранится в **Downloads/bim-diff-reports** домашнего каталога; точный путь печатается в терминале. Отправьте JSON организатору теста, указав версию пакета 1.0.1. Отчёты содержат сведения об устройстве.

Для сопоставимости используйте одну версию команды на всех устройствах. Не сравнивайте показатели программного рендера с аппаратным.

## Какие метрики доступны

- FPS, времена кадров, счётчики рендера, этапы подготовки, long tasks и доступные browser API.
- Системные CPU/RAM: Windows, macOS, Linux.
- CPU процессов выделенного Chromium через CDP; RAM процессов через ps/PowerShell. CPU может превышать 100%: 100% означает одно логическое ядро. Суммарный RSS может повторно учитывать общие страницы.
- macOS: доступные счётчики IOAccelerator; NVIDIA Windows/Linux: nvidia-smi, если установлен драйвер.
- Intel/AMD и некоторые версии macOS могут не отдавать загрузку GPU. Локальный запуск НЕ гарантирует все GPU-метрики. Недоступное сохраняется как null с причиной, а не как нулевая нагрузка.
- GPU-метрики ОС относятся ко всему устройству; браузерный GPU timer зависит от расширения WebGL. Системная RAM включает другие приложения и кеш ОС.

Сборщик опрашивает ОС примерно раз в секунду и сам создаёт небольшую нагрузку.
Vercel-версия не имеет доступа к этому локальному сборщику. Локальные серверы слушают только 127.0.0.1; модели не отправляются на сервер.

## Поддержка и диагностика

Проверено на macOS; выполнение на физических Windows/Linux требует проверки тестировщиком.
На Linux Chromium может потребовать системные библиотеки: https://playwright.dev/docs/browsers#install-system-dependencies . Launcher не запускает sudo и не меняет систему автоматически.
Если браузер не скачался, проверьте прокси/интернет и свободное место. Если порт занят, завершите предыдущий запуск.
Для помощи добавьте `--help` после URL в команде. `--headless` предназначен только для диагностики: он использует программный рендер и не подходит для аппаратного сравнения.

## IFCZIP (1.0.1)

Выберите «Свои IFC / IFCZIP / FRAG» и сценарий «Полный путь от IFC / IFCZIP». Можно смешивать IFC и IFCZIP. Архив должен содержать ровно один STEP-файл `.ifc`. Поддерживаются ZIP Store/Deflate; IFCXML, ZIP64, шифрование и многотомные архивы не поддерживаются. Лимиты: архив 256 MiB, распакованный IFC 512 MiB, 4096 записей.

Распаковка и проверка CRC выполняются в Worker, внутри измеряемой подготовки. JSON содержит исходные форматы/размеры/хеши, этапы `unzip-0`/`unzip-1` в миллисекундах и `unpackedBytes-0`/`unpackedBytes-1` в байтах. Время распаковки входит в `prepare-N`, поэтому их нельзя складывать. При попадании в кеш подготовленной модели распаковка пропускается и соответствующее измерение отсутствует.

## Исходники бенчмарка

- `packages/bim-diff-core/src/` — независимое ядро сравнения на TypeScript: нормализация, хеширование, сопоставление и план наложения. CLI работает в Node.js без GPU.
- `src/ifczip.ts` — ограниченная распаковка IFCZIP; `cache.ts`, `diff.worker.ts`, `worker-client.ts` — кеш и Worker ядра.
- `src/ifc-diff-wasm.ts` — загрузка Zig WASM и преобразование его JSON в `DiffArtifact`; `src/ifc-diff.worker.ts` — Worker для WASM-differ.
- `src/ifc-wasm-benchmark.ts` — метод сравнения `ifc-wasm-v1` для `BenchmarkRunner`.
- `src/ifc-preview.ts`, `src/ifc-preview-groups.ts`, `src/ifc-preview-import.ts` — 3D-превью: сцены, раскраска по diff и вызов готового `import.worker` для IFC → FRAG.
- `src/measurement.ts`, `src/results.tsx` — сбор метрик и отображение отчёта; входные данные рендерера описаны локальным контрактом.
- `bin/` — запуск браузера и системная телеметрия.
- `test/`, `packages/bim-diff-core/test/` — тесты.

```sh
npm ci
npm run check-types
npm test
npm run compare -- left-index.json right-index.json diff.json
```

CLI принимает подготовленные `ModelIndex`, а не IFC. Контракт находится в `packages/bim-diff-core/src/contracts.ts`.

## IFC WASM · Zig

Дополнительный метод сравнения: STEP-файлы разбирает и сравнивает Zig-ядро, собранное в WebAssembly. Метод сопоставляет `GlobalId` и один уровень параметров сущности; геометрия не тесселируется, поэтому изменение формы или положения внутри связанной сущности не видно. Объекты без `GlobalId` не участвуют. Результат — тот же `DiffArtifact`, что у TypeScript-ядра, с дополнительным полем `method`.

Нужен checkout `ifc` с `src/wasm.zig` и Zig 0.17 рядом с этим репозиторием (или `IFC_DIR`):

```sh
npm run build:wasm   # zig build wasm, public/wasm/ifc-diff.wasm, public/ifc-wasm-method.js
npm run compare:ifc -- a.ifc b.ifc out.json
npm run bench:ifc -- a.ifc b.ifc --repeats 5
```

`compare:ifc` печатает `DiffArtifact` (или краткую сводку с `--summary`), `bench:ifc` — таблицу этапов WASM. В `npm run dev:ui` метод выбирается в поле «Differ»; `npm start` добавляет то же поле в готовый runner через `public/ifc-wasm-method.js`.

### 3D-превью `ifc-wasm-v1`

После измеряемых прогонов метод показывает две сцены рядом: слева старая версия, справа новая. Неизменённые элементы остаются видимыми, но приглушены; удалённые подсвечены красным слева, добавленные — зелёным справа, изменённые — фиолетовым слева и жёлтым справа. Подсветка идёт по `GlobalId`, поэтому локальные id Zig-парсера и `web-ifc` могут не совпадать.

Превью использует тот же стек, что старый overlay-viewer: `@thatopen/fragments` + `three` + `web-ifc`. IFC → `.frag` выполняет тот же `import.worker`, который уже используется готовым runner; отдельная копия web-ifc для конвертации не нужна. Затем каждая модель загружается в свою сцену. Это второй проход по файлам, он выполняется после замеров и не входит в `wasmTotal`; метрики `previewTotalMs`, `previewConvertMs`, `previewLoadMs`, `previewHighlightMs`, `previewFragBytes`, `previewGeometries` и `previewTextures` лежат в `summary` отчёта.

До 32 MiB суммарного ввода превью стартует автоматически, для больших файлов показывается кнопка «Показать 3D-превью». Ошибка превью не отменяет отчёт. Изменение только геометрии внутри связанной сущности по-прежнему не видно: differ сравнивает `GlobalId` и параметры, а не тесселяцию.


`npm run build:wasm` дополнительно собирает `public/ifc-preview-app.js` и обновляет `public/wasm/ifc-diff.wasm` и `public/wasm/web-ifc.wasm`. Сам `public/ifc-preview-app.js` не хранится в git: его собирает `npm run build:preview`, а `npm pack` делает это автоматически через `prepack`. Отдельные копии `import.worker` и Fragments-worker не создаются: используются уже поставляемые с runner файлы `public/assets/import.worker-*.js` и `public/assets/worker-*.mjs`. В `dev:ui` wasm и import worker отдаются Vite-плагином.


Коммерческий пакет `document-preview`, его рендерер, сервисы приложения и UI-kit не входят в исходники этого репозитория. React-интерфейс можно собирать отдельно без движка (см. ниже); `npm start` запускает прежний готовый runner из `public/`. Основное ядро diff написано на TypeScript; WASM используется сторонним IFC-парсером и необязательным Zig-методом сравнения.

## Разработка React-интерфейса демки

```sh
npm ci
npm run dev:ui
```

Откройте `http://127.0.0.1:4180`. Production-предпросмотр: `npm run build:ui`, затем `npm run preview:ui`.

- `src/benchmark-app.tsx` — интерфейс: настройки, выбор файлов, запуск/отмена, экспорт JSON и место для сцены.
- `src/results.tsx` — таблицы и детализация отчёта.
- `src/style.css` — стили, обычные HTML-контролы без UI-kit.
- `src/ui-contracts.ts` — контракт подключения движка и цвета легенды.
- `src/main.tsx` — точка входа предпросмотра; подключает метод `ifc-wasm-v1`.

Предпросмотр выполняет только сравнение `ifc-wasm-v1`: для этого нужен собранный `public/wasm/ifc-diff.wasm` (`npm run build:wasm`). Выбор `overlay-v1` в предпросмотре возвращает пояснение — этот метод доступен в `npm start`. Для подключения своей реализации хост передаёт функцию:

```tsx
import { BenchmarkApp } from "./src/benchmark-app";
import type { BenchmarkRunner } from "./src/ui-contracts";

// yourRunner реализует контракт BenchmarkRunner в приложении-хосте.
<BenchmarkApp runProtocol={yourRunner} fixtureBaseUrl="/bim-research/" />
```

Функция получает DOM-контейнер сцены, два входных файла, настройки, AbortSignal, обработчики прогресса и частичных отчётов; возвращает BenchmarkReport. Хост отвечает за освобождение ресурсов и отмену. Встроенные тестовые пары загружаются по `fixtureBaseUrl`, набор ARC отображается только при `hasArcPair={true}`. Для своих файлов используется выбор на диске.

UI-сборка использует `publicDir: false` и отдельный `dist-ui/`: старые бандлы, WASM и коммерческий рендерер из `public/` в неё не попадают. Исходники `document-preview`, UI-kit и адаптер коммерческого движка здесь отсутствуют. Команды `npm start` и существующий release-архив не изменены.
