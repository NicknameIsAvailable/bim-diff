# BIM Diff — локальный бенчмарк

Сравнение BIM-моделей с наложением версий и метриками каждого прогона.
Здесь находятся готовый production runner, исходники локального launcher/сборщика и независимые модули бенчмарка.
Сборка фронтенда уже включена: основной монорепозиторий и его история не нужны.

## Для тестировщика: одна команда

Один раз установите **Node.js 22 или новее** с https://nodejs.org/ (npm/npx входят в установку).
Откройте PowerShell/Terminal и выполните:

```sh
npx --yes https://github.com/NicknameIsAvailable/bim-diff/releases/download/v1.0.1/bim-diff-benchmark-1.0.1.tgz
```

Клонировать репозиторий, устанавливать Git и вводить токены не нужно.
При первом запуске автоматически скачивается Chromium (несколько сотен мегабайт).
Последующие запуски используют кеш. Откроется отдельное окно браузера.
Не закрывайте терминал во время измерений. Закрытие окна браузера или Ctrl+C останавливает приложение.
Порты 4176 и 4177 должны быть свободны; одновременно запускайте только один экземпляр.

## Как провести тест

1. Закройте тяжёлые приложения, подключите ноутбук к питанию; запишите режим энергопотребления.
2. Используйте автоматически открывшийся Chromium: в другом браузере не будет привязанных CPU/RAM-метрик.
3. Выберите одинаковую пару файлов и сценарий на всех устройствах. В комплекте только небольшие тестовые наборы; рабочие IFC/FRAG выбирайте с диска.
4. Заполните сведения об устройстве. Выполните обычный протокол: прогрев + 5 измеряемых повторов с 30 секундами движения камеры. Диагностический короткий прогон не является замером производительности.
5. Держите вкладку видимой. Не двигайте окно между экранами и не меняйте масштаб во время прогона.
6. Нажмите экспорт JSON. Файл сохранится в **Downloads/bim-diff-reports** домашнего каталога; точный путь печатается в терминале. Отправьте JSON организатору теста, указав версию пакета 1.0.1. Отчёты содержат сведения об устройстве.

Для сопоставимости используйте одну версию команды на всех устройствах. Не сравнивайте показатели программного рендера с аппаратным.

## Какие метрики доступны

- FPS, времена кадров, счётчики рендера, этапы подготовки, long tasks и доступные browser API.
- Системные CPU/RAM: Windows, macOS, Linux.
- CPU процессов выделенного Chromium через CDP; RAM процессов через ps/PowerShell. CPU может превышать 100%: 100% означает одно логическое ядро. Суммарный RSS может повторно учитывать общие страницы.
- macOS: доступные счётчики IOAccelerator; NVIDIA Windows/Linux: nvidia-smi, если установлен драйвер.
- Intel/AMD и некоторые версии macOS могут не отдавать загрузку GPU. Локальный запуск НЕ гарантирует все GPU-метрики. Недоступное сохраняется как null с причиной, а не как нулевая нагрузка.
- GPU-метрики ОС относятся ко всему устройству; браузерный GPU timer зависит от расширения WebGL. Системная RAM включает другие приложения и кеш ОС.

Сборщик опрашивает ОС примерно раз в секунду и сам создаёт небольшую нагрузку.
Vercel-версия не имеет доступа к этому локальному сборщику. Локальные серверы слушают только 127.0.0.1; модели не отправляются на сервер.

## Поддержка и диагностика

Проверено на macOS; выполнение на физических Windows/Linux требует проверки тестировщиком.
На Linux Chromium может потребовать системные библиотеки: https://playwright.dev/docs/browsers#install-system-dependencies . Launcher не запускает sudo и не меняет систему автоматически.
Если браузер не скачался, проверьте прокси/интернет и свободное место. Если порт занят, завершите предыдущий запуск.
Для помощи добавьте `--help` после URL в команде. `--headless` предназначен только для диагностики: он использует программный рендер и не подходит для аппаратного сравнения.

## Разработка launcher

```sh
npm ci
npm test
npm start
npm pack
```

Публикация: архив npm pack прикрепляется к GitHub Release. GitHub Packages не используется: для скачивания npm-пакетов из этого registry нужна авторизация. GitHub Release позволяет запуск без аккаунта и без Git. Новые версии публикуются отдельными тегами.

В репозитории нет GitLab-интеграции, Vercel-настроек, секретов, source maps, пользовательских моделей и результатов измерений. Исходники фронтенда основного проекта не включены.

## IFCZIP (1.0.1)

Выберите «Свои IFC / IFCZIP / FRAG» и сценарий «Полный путь от IFC / IFCZIP». Можно смешивать IFC и IFCZIP. Архив должен содержать ровно один STEP-файл `.ifc`. Поддерживаются ZIP Store/Deflate; IFCXML, ZIP64, шифрование и многотомные архивы не поддерживаются. Лимиты: архив 256 MiB, распакованный IFC 512 MiB, 4096 записей.

Распаковка и проверка CRC выполняются в Worker, внутри измеряемой подготовки. JSON содержит исходные форматы/размеры/хеши, этапы `unzip-0`/`unzip-1` в миллисекундах и `unpackedBytes-0`/`unpackedBytes-1` в байтах. Время распаковки входит в `prepare-N`, поэтому их нельзя складывать. При попадании в кеш подготовленной модели распаковка пропускается и соответствующее измерение отсутствует.

## Исходники бенчмарка

- `packages/bim-diff-core/src/` — независимое ядро сравнения на TypeScript: нормализация, хеширование, сопоставление и план наложения. CLI работает в Node.js без GPU.
- `src/ifczip.ts` — ограниченная распаковка IFCZIP; `cache.ts`, `diff.worker.ts`, `worker-client.ts` — кеш и Worker ядра.
- `src/measurement.ts`, `src/results.tsx` — сбор метрик и отображение отчёта; входные данные рендерера описаны локальным контрактом.
- `bin/` — запуск браузера и системная телеметрия.
- `test/`, `packages/bim-diff-core/test/` — тесты.

```sh
npm ci
npm run check-types
npm test
npm run compare -- left-index.json right-index.json diff.json
```

CLI принимает подготовленные `ModelIndex`, а не IFC. Контракт находится в `packages/bim-diff-core/src/contracts.ts`.

Коммерческий пакет `document-preview`, его рендерер, сервисы приложения и UI-kit не входят в исходники этого репозитория. Поэтому сборка полного интерфейса из исходников здесь сейчас не предоставляется; `npm start` запускает готовый runner из `public/`. В исходниках оставлены только самостоятельные части бенчмарка. WASM относится к стороннему IFC-парсеру, ядро diff написано на TypeScript.
